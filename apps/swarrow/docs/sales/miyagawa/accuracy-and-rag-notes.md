# 回答精度・情報参照の仕組みメモ

作成日: 2026-03-12

## このメモの目的

営業で `回答精度はどう担保するのか` `RAGとは何か` `なぜ資料の整理で精度が上がるのか` を説明するためのメモ。

## まず一言でいうと

`回答の質は、AIモデルの性能だけでなく、必要な情報を探しやすく整理できているかで大きく変わります。`

## 短くいう版

`SwarrowCallは、自治体のFAQや業務資料をもとに答えるので、一般的なAIより業務に沿った回答がしやすいです。さらに、Azure AI Document Intelligenceをベースに、弊社で文書整理プログラムをチューニングしているため、AIが必要な情報を見つけやすくなっています。難しい内容は人に引き継ぐので、無理に答えさせない運用もできます。`

## 詳しくいう版

`SwarrowCallの回答品質は、AIモデルそのものだけで決まるわけではありません。Azure AI Document Intelligenceをベースに、弊社で文書整理プログラムをチューニングし、自治体ごとのFAQや業務資料をAIが参照しやすい形に整えることで、質問に合う情報を見つけやすくしています。例えば、住民課のマイナンバーカード関連でも、受け取り、暗証番号、電子証明書、持ち物、代理人手続きが混ざった資料のままでは、必要な情報を見つけにくくなります。これを話題ごと、手続きごとに整理すると、AIが必要な情報を見つけやすくなり、結果として回答が安定しやすくなります。さらに、よくある質問や例外条件を運用しながら追加していくことで、精度を継続的に改善できます。難しい問い合わせは人に引き継ぐ前提にすることで、実運用上の品質も担保できます。`

## 専門用語を使わない説明

### RAGとは

- `既存のFAQや業務資料を参照して答える仕組み`

補足:

- その後、そのまとまりを読んで回答する

営業での言い換え:

- `AIが読みやすい形に整理したFAQや業務メモ`
- `見出しや項目をそろえて整えたナレッジ`

## なぜ資料の整理で精度が上がるのか

### 基本の考え方

AIは、資料を丸ごと全部見て答えるのではなく、`質問に関係ありそうな部分` を先に探してから答える。

そのため、情報の区切り方が悪いと、次のようなことが起こる。

- 本来セットで読むべき情報が分断される
- 重要な注意事項だけ別のかたまりに切れてしまう
- 質問に関係する部分が上位に上がらず、別の情報を参照してしまう

### 具体例

質問:

`マイナンバーカードの電子証明書更新には何が必要ですか？`

資料が整理されていない場合:

- 受け取り方法
- 暗証番号再設定
- 電子証明書更新
- 代理人手続き
- 必要な持ち物

が長いPDFの中に混在している。

この状態だと、AIが `電子証明書更新` の説明を見つけても、最後に書かれた `持ち物` や `例外条件` が別のかたまりに切れて、うまく参照されないことがある。

資料が整理されている場合:

- `電子証明書更新の対象者`
- `必要な持ち物`
- `受付場所`
- `注意事項`
- `代理人の場合`

のように話題ごとにまとまっている。

この状態だと、AIは必要な情報のまとまりを見つけやすくなり、回答の抜けや取り違えが減りやすい。

### つまり何が起こるのか

- `検索しやすくなる`
  - 質問に合う情報が見つかりやすい
- `ノイズが減る`
  - 関係ない情報を一緒に読ませにくくなる
- `回答が安定する`
  - 必要な条件や注意事項を含めて答えやすい
- `改善しやすい`
  - 間違えた箇所だけ後から直しやすい

## SwarrowCallで使っている文書解析の説明

営業での言い方:

`SwarrowCallでは、MicrosoftのAzure AI Document Intelligenceをベースにしながら、弊社で文書整理プログラムをチューニングし、文書の見出し、段落、表などの構造を踏まえてAIが参照しやすい形に整えています。`

補足:

- Azure AI Document Intelligence の `layout model` は、文書構造を解析し、Markdown または text 形式の構造化表現を出力できる
- Microsoft Learn では、`document structure` を認識し、見出しと本文の関係を保ちながら扱えると説明している
- Microsoft Learn では、`text data chunking strategies play a key role in optimizing RAG responses and performance` と説明しており、文書構造ベースの chunking が回答の関連性改善に寄与するとしている
- paragraph roles として `title` `sectionHeading` `pageHeader` `pageFooter` などを予測できる

営業での着地:

`単にPDFを入れているのではなく、Microsoftの文書構造解析をベースに、弊社で文書整理プログラムをチューニングし、見出しや段落のまとまりを見ながらAIが参照しやすい形に整えているのがポイントです。`

## SwarrowCallでどう対応するか

### 1. AIが参照しやすい形に整理する

- Azure AI Document Intelligence をベースに、弊社で文書整理プログラムをチューニングし、大きな見出しや話題のまとまりを見て情報を区切る
- 手続きやテーマが混ざらないように、まとまりを保つ
- 重要な注意事項や例外条件が分断されにくいようにする

### 2. それでも完全でない文書は手で調整できる

- 文書によっては、自動の区切りだけで100%きれいにならないことがある
- その場合は、FAQや業務メモを整理し直して、AIが参照しやすい形にできる
- これにより、運用しながら回答品質を上げていける

### 3. 答えにくい内容は人に返す

- 何でもAIに答えさせるのではなく、難しい質問は引き継ぐ
- これも実運用品質を上げるための設計

## 数字で見るなら何を測るか

RAG型の窓口AIでは、`モデルの精度` だけではなく、`システム全体としての品質` を見る。

- `AI完結率`
  - AIだけで対応が完了した割合
- `回答正答率`
  - 評価用の質問セットに対して正しく答えられた割合
- `引き継ぎ適正率`
  - AIが答えるべきでない質問を適切に人へ戻せた割合
- `再問い合わせ率`
  - AI回答後に同じ趣旨で再度問い合わせが来た割合

## NotebookLMとの違い

### 安全な言い方

`NotebookLMは、Googleが提供する調査・学習支援向けのツールです。一方、SwarrowCallは、自治体や事業者の問い合わせ対応や電話・チャット・架電業務を運用するための基盤です。用途が違います。`

### 共有に関する補足

NotebookLMの共有は `同じ組織内だけ` と言い切らない方が安全。

- 2026-03-12時点で、Googleの公式ヘルプには `個人Gmailは最大50人まで私的共有可能` とある
- Google公式ブログには `公開共有` も案内されている
- ただし、`Workspace / Education の公開共有は同一ドメイン制限` という注記がある

つまり、次の言い方が安全。

`NotebookLMは共有機能がありますが、共有の考え方はアカウント種別に依存します。少なくともSwarrowCallのような対外窓口運用や電話対応を前提にした共有・運用モデルとは異なります。`

### 電話対応との違い

GoogleはNotebookLMを `research and learning assistant` と位置付けている。

このため、比較としては次が言いやすい。

- `NotebookLMは資料を理解・整理するためのツール`
- `SwarrowCallは問い合わせ対応と連絡業務を実運用するためのツール`
- `SwarrowCallは電話応答、チャット、架電、引き継ぎ、運用改善まで含めて設計されている`

### 外部連携について

2026-03-12時点で確認できた Google 公式情報では、NotebookLM が対応する主なソース種別として次が案内されている。

- Google Docs
- Google Slides
- PDF
- text / Markdown files
- web URLs
- copied text
- public YouTube URLs
- audio files

このため、少なくとも公式情報ベースでは次の言い方が安全。

- `NotebookLMはWebサイトをソースとして読み込むことはできます`
- `ただし、公式情報で確認できたのはソース取込とノートブック共有までです`
- `LINE連携や、ホームページ埋め込み用の問い合わせウィジェットとしての利用は、公式の機能説明では確認できませんでした`

営業での比較表現:

`NotebookLMは資料を読ませて調べる用途には向いていますが、LINE連携、ホームページ埋め込み、電話応答のような対外窓口運用を前提にしたツールとしては案内されていません。`

### 比較で避けたい言い方

- `NotebookLMは同じ組織内のメールアドレス内でしか共有できません`
  - 2026-03-12時点では一般化しすぎ
- `NotebookLMはチャンクが汚いです`
  - 公式仕様として確認できない
- `他社にはこの仕組みがほとんどありません`
  - 根拠が弱い

### 比較で使いやすい言い方

- `一般的なAIツールでは、資料の分割や参照のされ方を細かく意識しにくいことがあります`
- `SwarrowCallは、回答時にどの情報を参照しやすくするかを重視して設計しています`
- `資料を入れて終わりではなく、運用しながら回答品質を改善できる点が違いです`
